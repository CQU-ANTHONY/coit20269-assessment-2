# Cordova setup — Android build & camera (#18)

Wraps `client/www/` as a Cordova hybrid app with **cordova-plugin-camera** so the listing form can capture photos on a device/emulator for the Week 12 demo.

## Prerequisites

- **Node.js 24** and **npm** (same as the rest of the project)
- **Java JDK 17+** (Temurin or Oracle)
- **Android Studio** with:
  - Android SDK Platform (API matching `android-targetSdkVersion` in `config.xml`, currently 35)
  - Android SDK Build-Tools
  - Android Emulator **or** a physical device with USB debugging
- Environment: `ANDROID_HOME` / `ANDROID_SDK_ROOT` set; `platform-tools` on `PATH`

Cordova CLI is installed as a **client** dependency (`npx cordova`); you do not need a global Cordova install.

## One-time project setup

From the repo:

```bash
cd client
npm install
```

Add the Android platform and camera plugin (creates local folders that are **gitignored**):

```bash
npx cordova platform add android
npx cordova plugin add cordova-plugin-camera
```

Or use the npm scripts:

```bash
npm run platform:add:android
npm run plugin:add:camera
```

`package.json` already lists `cordova-android` and `cordova-plugin-camera` so versions stay consistent. Re-run the add commands after a clean clone (because `platforms/` and `plugins/` are not in git).

## Build & run (Android)

```bash
cd client
npx cordova build android          # or: npm run build:android
npx cordova run android            # emulator or USB device; or: npm run run:android
```

Point the app at a reachable HTTPS API before demoing: edit `API_BASE` in `www/js/api.js` (local HTTPS or the Render URL from #13). Emulators use `10.0.2.2` to reach the host machine’s localhost if needed.

## What is gitignored (do not commit)

| Path | Why |
|---|---|
| `client/platforms/` | Native Android project generated by Cordova |
| `client/plugins/` | Fetched plugin copies |
| `client/www/cordova.js` | Injected at prepare/build time |
| `client/www/cordova_plugins.js` | Plugin registry injected at build time |

Committed Cordova inputs: `client/config.xml`, `client/package.json`, and `client/www/` (HTML/JS/CSS).

## How the camera feeds the listing form

1. On device, Cordova fires `deviceready`; `form.js` waits for that before using the plugin.
2. **Take photo** (`#listing-photo-camera`) calls `navigator.camera.getPicture` with `DestinationType.DATA_URL`.
3. The JPEG is stored as a `data:image/jpeg;base64,...` string in `#listing-photo` and shown in the preview.
4. On save, that value is sent as the listing `photo` field via the existing API helpers.
5. In a desktop browser (no plugin), the same button falls back to the hidden file input or a pasted URL.

`index.html` loads `cordova.js` **before** jQuery (Cordova convention). The file appears only after `cordova prepare` / build.
